## Methods

One full generation from a seeded random-init net, orchestrated per
`scripts/run_pilot.py` with the run layout `data/runs/pilot0/{selfplay,
checkpoints,eval}` (check 7 contract). Records are v3: model-stamped,
legal-index list included, truncation as WDL 3 (D-008). Training used the
legal-masked policy softmax (D-015 contract) and excluded truncated
records from the value loss. Evaluation ran the pinned D-019 settings
against the frozen population exactly as configured in D-017.

## Raw results + uncertainty

**Self-play (gen 0, random-init net):** 300 games → 17,237 recorded
positions; **170/300 games truncated at the 300-ply cap (56.7%)**;
0 resignations (a random-init value head never crosses the threshold);
~60 min wall at 4 threads ≈ 12 s/game — untrained games run long; the
gen-19-net probe measured ≈3 s/game at the same budget (journal
H4-2026-09-09-coreml-fix-01), so per-generation cost falls as play
sharpens.

**Pre-training checks on the real shard:** all green — masked-softmax
illegal mass exactly 0 and legal mass = 1 (check 1); all stored target
and played indices legal (check 2); WDL domain valid with 12,806
truncated records excluded from the value loss (check 3); tiny-batch
overfit KL 0.093, policy argmax 15/15, value 15/15 on the trained
records, with the initial "failure" traced to (a) comparing against the
soft-target entropy floor and (b) including the val holdout — criterion
corrected, journal-noted (check 4); save/resume bitwise-identical at
step 2110 (check 5); eval noise structurally off + pinned config
(check 6, D-019); eval/training trees disjoint by audit (check 7).

**Training (3 epochs, 16,893 train / 344 val):** loss decreased

top-1 4–5% (above the ~1–2% uniform-legal chance level); val value
accuracy 42–46% over the 94 non-truncated val records; ~772 pos/s on MPS.

## Failures

1. **Eval harness slip (mine, caught by the diagnosis rule):** the first
   eval pass showed identical 0/2/28 against ALL opponents including
   B-RND. Investigation order rules→signs→search→data (task 11) led to
   the game records: opponents' replies were identical across pairings —
   the zsh loop had passed each opponent's flags as ONE argument, so
   every opponent fell back to the default alpha-beta backend (all three
   matches were vs B-HEU). The driver (`run_pilot.py`, proper argv lists)
   does not have this bug; the shell rerun with explicit argv produced
   the coherent table above. Kept as a worked example of why identical
   results across supposedly different conditions are a harness alarm.
2. `run_h4_checks.sh` initially invoked system `python3` (broken anaconda
   torch) for check 5 — pinned to the project venv.

## Limits / confounders

30 games/opponent (pilot volume); one seed end-to-end; gen 0 only — the
loop's ITERATION (gen 1+) is exercised in structure but not run here;
value-head signal thin at gen 0 (74% of records truncation-masked).

## Interpretation

**Pipeline validated per plan ch. 5:** the complete loop runs at small
budget; metrics are non-degenerate (policy above chance and not
collapsed, value learning above base rate, losses decreasing); and the
performance profile has a clean diagnosis — one generation of
random-init self-play yields a net that already **beats legal-random
100–0** (genuine learning signal, not noise) while losing to the sharp
heuristic and the 6400-sim searcher, with rules/signs/search each
independently validated (H2/H3) so the gap is a DATA/iteration gap, not
a defect. No capacity increase is warranted (task 11): the indicated
next lever is more generations, exactly what the loop is for.

**D-011 confirmation inputs for the H1 freeze (D-012):** 128/32 sims are
feasible at study scale — worst case (gen 0, long games) ≈ 12 s/game
wall at 4 threads, improving toward ≈3 s/game as play sharpens; training
cost negligible next to generation. The 300-ply cap truncates 56.7% of
gen-0 games — the cap value remains workable *because* truncation is a
separate reported outcome (D-008); the protocol's cap-sensitivity
procedure is demonstrably load-bearing and stays.

## Decision

**continue** — H4 exit criteria met; present `docs/protocol.md` with
these pilot-confirmed values for the G-FREEZE review (D-012).
