## Methods

`scripts/run_comparison.py` gains four options, identical for both arms
and off by default:

| Option | Effect |
| --- | --- |
| `--warm-start` | generation g > 0 trains with `--init <run>/checkpoints/gen(g-1)/<arch>-e<E-1>.pt` (model weights only; optimizer and schedule restart, as the trainers already implement) |
| `--window W` | the training `--data` list holds the shard globs of generations max(0, g-W+1) … g (default 1 = Study 1) |
| `--run-prefix P` | run directory `data/runs/P-<arm>-s<seed>` (Study 2 will use `cmp2`, so Study-1 directories are never written) |
| `--dry-run` | prints every command line, writes nothing, runs nothing |

A `driver-config.json` is written at the root of a run (arm, seed,
generations, games, epochs, warm_start, window, prefix) so a reader of
the records can tell the two regimes apart without parsing logs.
Self-play, export, evaluation and the per-generation resume logic are
untouched.

Regression test `scripts/test_driver_equivalence.py`: for four Study-1
runs (grid s1, graph s1, grid s4, graph s5) and ten generations each, the
dry-run training command under default options is compared with the
recorded `train-config.json` (data globs, seed, epochs, init = none) and
the self-play command with the recorded manifest (seed, games, sims
full/cheap, model generation). Then for `--warm-start --window 3
--run-prefix cmp2` the test checks that only the data list and the
initialisation flag differ from the default command lines (modulo the
run directory), that generation 0 has no initialisation, and that
generation g initialises from generation g-1.

Trainer smoke (actual code path, no self-play): each trainer run on the
existing Study-1 shards of generations 1-3 of seed 1 (three globs) with
`--init` from that run's generation-2 checkpoint, one epoch capped at
20 steps, output in the session scratchpad.

## Limits / confounders

The pipeline doc asked for a one-generation self-play smoke per arm at
50 games. It was replaced by the trainer-level smoke above, which
exercises the two parts that changed (initialisation from a checkpoint,
multi-generation shard list) on existing shards at no self-play cost;
the driver's full execution path with the new options will first run in
the pilot (task 2, G-SPEND). The dry-run equivalence is a command-line
check, not a bit-level reproduction of Study 1 (which was established
separately by the fresh-environment reproduction, report ch. 10).
